## 1. 진단: 왜 거절당했나

거절 메일에는 구체적 사유가 없고 "콘텐츠 부족 또는 낮은 콘텐츠 품질"이라는
일반론만 있었음. 코드와 실제 사이트를 직접 감사해서 찾은 실제 원인들:

### 치명적 (단독으로 거절 사유가 되는 것들)

1. **크롤러가 따라갈 수 있는 내부 링크가 0개였음**
   - 상단 메뉴·푸터 링크 전부가 `href="#" onclick="navigate(...)"`
   - 페이지당 21개 × 15페이지 = 316개 링크가 전부 크롤링 불가
   - 구글이 사이트맵 40개 중 27개만 인지하고 있던 직접적 원인

2. **개인정보처리방침에 애드센스 관련 고지가 아예 없었음**
   - 제3자 광고 쿠키, DoubleClick, 맞춤광고 거부 방법 = 애드센스 **필수 요구사항**
   - 이용약관에도 광고 게재 조항 없었음

3. **홈페이지 대표 기능이 이메일만 받고 고장나 있었음**
   - "🔔 하락 알림 받기" 폼이 `/api/alerts` 로 POST → **그 함수는 저장소에 존재한 적 없음**
   - 누르면 404 → JSON 파싱 실패 → `❌ Unexpected token '<', "<!DOCTYPE"...` 노출
   - 심사자가 첫 화면에서 가장 눈에 띄는 기능을 눌렀다면 정확히 이걸 봤을 것

4. **모든 페이지가 광고로 시선을 유도하고 있었음**
   - 로딩 메시지: `"⏳ 데이터 불러오는 중... 단, 아래 광고가 표시될 수 있습니다!"`
   - 광고에 주의를 끄는 문구는 애드센스 정책 위반 소지

5. **사이트의 실제 제품이 아무에게도 안 보였음**
   - 홈페이지를 그냥 열면 빈 검색창만 있고 아무것도 계산되지 않음
   - 티커를 직접 타이핑해야만 결과가 나오는데, 크롤러도 심사자도 그렇게 하지 않음
   - 블로그의 "지금 확인하기" 버튼(유일한 진입 경로)도 렌더링이 빠져 있어 존재하지 않았음

### 콘텐츠 품질

6. **계산기 페이지에 설명이 거의 없었음** — 보이는 텍스트 843~1,280자, 대부분 버튼 라벨
7. **블로그 20~25번이 스텁** — 550~770자인데 "8분 읽기"로 표기
8. **투자 권유성 표현** — "MDD -30% 이하에서 매수를 검토하는 전략이 유효합니다",
   "-20% 지점에서 손절매", RSI 구간별 매수/매도 지시, 14번 글 제목 "언제 주식을 사야 하는가"
   → 금융(YMYL) 주제에서 자격 없이 쓰면 거절 사유
9. **자동 생성된 얇은 종목 페이지 39개** — 각 423자, 내용을 2문장에서 잘라내고
   그라데이션 페이드 + "무료로 전체 보기 →" 버튼으로 클릭 유도 (전형적 저품질 패턴)
10. **E-E-A-T 신호 없음** — 저자 정보, 출처, 연락처 이메일 전부 없었음

### 기술 부채

11. **블로그 데이터 60KB가 모든 페이지에 복제** — 게다가 낡아서 14개 페이지가
    수정 전 옛 텍스트를 그대로 서빙하고 있었음
12. **내부 오류가 사용자에게 노출** — "백엔드 오류 / 무료 한도(분당 8회·일 800회)"

## 4. 콘텐츠 전략 (영상 조언 반영)

"주제를 좁혀야 이긴다"는 조언이 이 사이트에도 정확히 해당됨.

- **블로그 25편**("MDD란 무엇인가", "투자 심리학" 등)은 레드오션. 아무리 잘 써도
  구글이 "새로운 정보"로 인정하기 어려움 → 여기에 더 투자하지 말 것
- **계산기 + 종목 실데이터 리포트**가 이 사이트의 진짜 차별점. 대형 언론사도
  증권사 블로그도 "실제 API로 계산한 종목별 하락 구간 표"는 안 만듦
- 타겟도 "주식 투자자 전체"가 아니라 **"미국 주식 하는 한국 개인투자자(서학개미)"** 로 좁힘

### 종목 리포트 설계 원칙 (예전 실패를 반복하지 않기 위해)

옛 버전은 내용을 잘라내고 클릭을 유도하는 티저였음. 새 버전은 **페이지 하나가
그 자체로 완결된 답**이어야 함:

- 현재 낙폭 / ATH / 현재가 (실계산값)
- **역대 주요 하락 구간 표** (고점일·고점가·저점일·저점가·하락률·회복 소요일) ← 핵심 차별점
- 연환산 변동성, SPY 대비 비교
- 데이터 기준일 + "매주 자동 갱신" 신선도 고지

## 6. ✅ 해결됨: 삭제한 종목 페이지 24개 404

**발견 경위**: 구글 검색에 `https://mddcalc.com/stock/baba.html` 이 노출되는데
(2026-07-09 색인) 클릭하면 404. `d1af0ea` 에서 얇은 종목 페이지 39개를 지울 때
그중 24개가 이미 색인된 상태였음.

`noindex` + 링크 없음이라 안전하다고 판단했던 게 오판이었다. noindex는 *앞으로의*
색인을 막을 뿐, *이미* 색인된 URL에는 소용이 없다.

**조사 범위**: 저장소 히스토리의 HTML 83개, 과거 사이트맵 전 버전의 URL 79개를
대조. 구글에 제출됐다가 사라진 URL은 그 24개가 전부였음.
`chapter1-3.html`(소설 콘텐츠가 실수로 배포됐던 흔적)도 사라졌으나 사이트맵에 없었고
19시간만 존재해 조치하지 않음.

**해결**: `TICKERS` 를 39개로 복원해 URL을 되살림. 리다이렉트 대신 복원을 택한 이유는
이미 색인·노출까지 얻은 URL이고, 이번엔 423자 티저가 아니라 실데이터 리포트를 서빙하기 때문.

### 이 과정에서 함께 잡은 것들

1. **링크 편중** — `buildRelatedTickersHtml` 이 목록 앞에서 6개를 잘라 쓰고 있어서
   39개 페이지가 전부 같은 종목만 가리킬 뻔했다. 순환식으로 바꿔 모든 종목이
   인바운드 링크 6개씩 갖도록 함
2. **분량 부족** — 복구 직후 평균 1,161자. 39개가 사이트맵 79개 중 절반이라
   "찍어낸 페이지" 패턴이 될 위험. 시세로 계산 가능한 지표 2종(하락 구간별 발생 횟수,
   회복 통계)을 추가해 **평균 1,886자**로
3. **회복 통계 오류** — 고점 대비 0.5%짜리 미세 등락까지 "하락 구간"으로 세는 바람에
   BABA가 "42개 구간, 회복 중앙값 5일"로 표시됐다. -10% 이상만 집계하도록 수정
   (→ 7개 중 6개, 중앙값 105일)
4. **벤치마크 비교 사실 오류** — "같은 기간"이라 써놓고 SPY의 자기 전체 기간을
   붙여넣고 있었다. BABA(2014년 상장) 페이지가 2006년부터의 SPY 낙폭과 비교되어
   벤치마크가 과장됨. 종목별 기간에 맞춰 SPY를 잘라 재계산하도록 수정
   (BABA 기준 SPY 최대 낙폭 -56.5% → **-34.1%**)

## 9. 2026-07-28: 색인 404 처리와 검색어 대응

### 색인 오류 "찾을 수 없음(404)" — `https://mddcalc.com/api/alerts`
원인은 새로 생긴 문제가 아니라 **이미 고친 버그의 잔상**이다. 예전 홈페이지의
"🔔 하락 알림 받기" 폼이 이 주소로 POST 했는데 그 함수는 저장소에 존재한 적이 없었다.
폼은 제거했지만 그 사이 구글이 URL을 알아버려서, 크롤러가 계속 찾아왔다가(최종 크롤링
2026-07-18) 404를 받고 리포트에 남은 것. 영향 페이지 1개, 사이트의 다른 URL과는 무관.

조치: `api/alerts.js`를 만들어 **410 Gone + JSON**을 돌려준다.
- 404는 "일시적으로 없음"이라 구글이 한동안 반복 크롤링하지만, 410은 "영구 삭제"라
  색인에서 더 빨리 떨어진다
- 캐시된 옛 화면이 아직 POST하더라도 HTML 대신 JSON이 가므로
  `Unexpected token '<'` 같은 날것의 에러가 사용자에게 노출되지 않는다
- `robots.txt`로 `/api/`를 막지는 **않았다**. 막으면 구글이 410을 보러 오지도 못해서
  오히려 URL이 리포트에 더 오래 남는다

### 검색어 대응 (3개월 실적 기준)
실적을 보면 클릭이 붙는 건 도구 이름(`mdd 계산기` 11클릭/41노출)이고,
**노출은 잡히는데 클릭이 0인 쪽이 종목 검색어**였다 — `schd mdd` 0/16, `qqq mdd` 0/16,
`고점대비 하락률` 0/10, `soxl mdd` 1/15. 즉 종목 페이지가 후보에는 오르는데 눌리지 않는 상태.

`scripts/generate-stock-pages.js`에서 손본 것:
1. **제목을 검색어 형태에 맞춤** — `SOXL MDD 실데이터: 역대 하락 구간·회복 기간 전체 정리`
   → `SOXL(반도체 3배 레버리지) MDD·고점 대비 하락률 총정리`.
   옛 제목에는 "고점 대비 하락률"이라는 표현 자체가 없었다
2. **설명문 맨 앞에 실제 숫자** — "현재 고점 대비 하락률은 -32.4%입니다".
   같은 순위에서도 숫자가 먼저 보이는 쪽이 클릭을 더 가져간다
3. **`<h1>` 추가** — 종목 페이지 39개에 h1이 **하나도 없었다**
4. **한글 종목명 도입**(`TICKER_NAMES`) — 제목·설명·h1·허브 앵커 텍스트에 "테슬라",
   "엔비디아"를 넣는다. 그 전에는 사이트 어디에도 한글 종목명이 없어서
   "테슬라 하락률" 류 검색어로는 후보에 오를 근거가 없었다
5. **종목 30개 추가** (39 → 69) — 양자컴퓨팅(IONQ·RGTI·QBTS), 원전/전력(OKLO·SMR·VST·CEG),
   개별 2배(TSLL·NVDL·CONL), ETF(SOXX·IVV·QLD·TLT·GLD), 그 외(HOOD·SOFI·APP·ORCL·
   ASML·MRVL·CRWD·ANET·RKLB·JOBY·MARA·LLY·COST·UNH·V)

**홈페이지 제목은 건드리지 않았다** — `mdd 계산기` 검색어에서 CTR 27%로 잘 먹고 있어서
바꿀 이유가 없다.

### 생성기 자체의 내구성
종목이 69개로 늘면 상장폐지·티커 변경·무료 플랜 미지원 등으로 한 종목이 실패할 확률도
같이 오른다. 예전 코드는 그 에러가 그대로 올라가 **주간 갱신 전체가 죽는** 구조였다.
- 실패한 종목은 건너뛰고 나머지를 계속 생성 (벤치마크 SPY 실패 시에만 전체 중단)
- 사이트맵·허브 링크에는 **파일이 실제로 있는 종목만** 넣는다.
  실패분까지 넣으면 구글이 없는 URL을 크롤링해 404를 받고, 그게 정확히 지금 고친
  색인 오류와 같은 종류의 문제가 된다
- 갱신 못 한 종목은 사이트맵 `lastmod`도 예전 날짜를 유지

### 적용 방법
종목 페이지 HTML은 생성기를 돌려야 바뀐다. 이 변경이 main에 들어간 뒤
**Actions 탭 > Refresh stock report pages > Run workflow**로 한 번 수동 실행하면
69개 페이지·사이트맵·tools.html이 전부 새 형식으로 갱신된다
(종목당 8초 대기라 10분쯤 걸린다). 안 돌려도 매주 월요일 스케줄에 자동 반영된다.

## 10. 2026-07-29: 한국 주식 조회 추가 + 차트 색 교체

### 차트 색
경쟁 사이트(mdd.toyon.kr) 비교 중 나온 요청. 두 차트의 색을 맞바꿨다.
- 고점 대비 하락률 차트: 빨강 `#e53e3e` → 파랑 `#3182ce`
- 주가 흐름 차트: 파랑 `#3182ce` → 빨강 `#e53e3e`

### 한국 주식(KRX) 조회
**왜 지금까지 안 됐나**: Twelve Data 무료(Basic) 플랜은 미국 거래소·환율·암호화폐만
포함하고 한국거래소(XKRX)는 유료 플랜(월 $29~)부터다. 키를 아무리 넣어도 무료로는 안 나온다.

**한 것**: KRX 종목만 별도 경로로 분리했다. 미국 종목 경로는 그대로 둔다.

| 파일 | 내용 |
|---|---|
| `api/kr/time-series.js` (신규) | Yahoo Finance chart 엔드포인트(키 불필요)로 KRX 일봉을 받아 **Twelve Data와 동일한 `{values:[{datetime,open,high,low,close}]}` 형태**로 변환해 반환 |
| 15개 페이지 공용 JS | `KR_STOCKS` 표(한글 종목명 → 코드) + `resolveSymbol()` 추가. 한국 종목이면 `/api/kr/time-series`, 아니면 기존 경로 |
| `index.html` | 원화 표기(`money()`), 자주 찾는 종목 칩, TradingView 심볼 변환(`005930.KS` → `KRX:005930`) |

설계 시 신경 쓴 것:
- **응답 형태를 일부러 Twelve Data에 맞췄다.** 프론트엔드의 계산·차트 코드는 한 줄도
  안 바뀌었고, 나중에 데이터 소스를 갈아끼울 때도 `fetchDaily()` 하나만 고치면 된다
- **6자리 코드만 들어오면 `.KS` → `.KQ` 순으로 시도**한다. 사용자가 코스피/코스닥을
  구분해서 입력할 필요가 없다
- **조회된 종목명을 화면에 표시**한다. "삼성전자"라고 쳤을 때 실제로 뭐가 조회됐는지
  (`삼성전자 (005930.KS)`) 사용자가 확인할 수 있어야 종목명 표가 틀렸을 때 바로 드러난다
- **"없는 종목"과 "서버 연결 실패"를 다른 문구로** 안내한다. 장애를 "코드를 확인하세요"로
  안내하면 사용자가 멀쩡한 코드를 계속 고쳐 넣게 된다
- **SPY 비교에 환율 주의 문구**를 붙였다. 한국 종목은 원화, SPY는 달러 기준이라
  환율 변동이 빠져 있다. 이 고지 없이 나란히 놓으면 사실과 다르게 읽힌다

### 설계를 한 번 갈아엎은 이유 (중요)

처음에는 `api/kr/time-series.js` 서버리스 함수를 만들어 **사용자가 버튼을 누르는 순간**
야후에 요청하도록 했다. 이건 틀린 설계였고 배포 전에 버렸다.

야후 chart 엔드포인트는 공식 지원 API가 아니다. 형식이 바뀔 수도, IP 단위로 429가 걸릴
수도 있고, 서버리스는 IP를 공유하니 트래픽이 늘수록 더 잘 걸린다. 그걸 조회 경로에 두면
**하필 심사자가 눌렀을 때 기능이 눈앞에서 고장나는** 구조가 된다.
이 저장소는 이미 그것 때문에 한 번 당했다 — 6장의 `/api/alerts` 404가 정확히 같은 모양이다.

그래서 **불안정한 호출을 전부 빌드 시점으로 옮겼다.**

| | 버린 설계 | 지금 설계 |
|---|---|---|
| 야후 호출 시점 | 사용자가 조회할 때마다 | GitHub Actions가 하루 한 번 |
| 브라우저가 읽는 것 | 서버리스 응답 | `/data/kr/{code}.json` 정적 파일 |
| 소스가 막히면 | **그 순간 조회 실패** | 지난 데이터로 계속 서빙, 사이트 영향 없음 |
| 한 종목이 실패하면 | 그때마다 실패 | 그 종목만 지난 데이터 유지 |

MDD는 전일 종가 기준 지표라 실시간일 필요가 없다 (사이트도 그렇게 안내하고 있다).
실시간성을 포기해서 얻은 게 없고, 안정성만 얻었다.

### "버튼은 있는데 눌러도 안 되는" 상태를 못 만들게 함

생성기가 **UI가 한국 종목을 약속하는 자리 세 곳을 전부 직접 쓴다**:
`KR_STOCKS` 표(15개 HTML), 바로가기 칩, 지원 종목 목록. 셋 다 *실제로 파일이 만들어진*
종목으로만 채워진다. 그래서 목록에 있는데 데이터가 없는 종목은 존재할 수 없다.
Actions가 아직 안 돌았으면 셋 다 비어 있다 — 그게 정직한 상태다.

부수 효과로 **한글 종목명이 페이지에 실제 텍스트로 들어갔다.** 9장에서 지적한
"사이트 어디에도 한글 종목명이 없어 '테슬라 하락률' 류 검색어에 오를 근거가 없다"는
문제와 같은 맥락이다.

그 둘만 저장한다. 날짜는 에포크 이후 일수(정수), 원화는 정수. 종목당 약 60~100KB.
