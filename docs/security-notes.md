# 보안 점검 메모

전체 코드 점검(2026-08-05)에서 고친 것과, **일부러 안 한 것**을 적어 둡니다.
안 한 쪽이 더 중요합니다 — 나중에 "이건 왜 없지?" 하고 추가했다가 사이트가 깨지는 걸 막기 위한 기록입니다.

---

## 고친 것

### 1. `/api/twelve-data/time-series` — 우리 유료 키를 대신 쓰는 프록시

이 주소는 아무나 부를 수 있었고, 부르는 만큼 우리 **일일 한도(800회)** 가 깎였습니다.
스크립트로 몇 분만 돌리면 한도가 바닥나 진짜 방문자가 조회를 못 하는 상태가 됩니다.

- **입력 검증** — `symbol` 은 프론트엔드의 `isValidTickerFormat()` 과 같은 규칙(최대 20자),
  `interval` 은 허용 목록, `outputsize` 는 1~5000 으로 자릅니다. 검증에 실패하면 업스트림까지 가지 않습니다.
- **Origin 검사** — 도메인을 하드코딩하지 않고 *요청이 들어온 Host* 와 Origin 이 같은지만 봅니다.
  그래서 도메인을 바꾸든 Vercel 프리뷰에서 열든 그대로 동작하고, 남의 사이트에서 부르는 것만 막힙니다.
  Host 헤더가 없으면 막지 않습니다(사이트가 멈추는 쪽이 더 나쁨).
- **IP별 속도제한** — 1분에 20회. 웜 인스턴스 메모리 기준이라 완벽하지는 않지만 문턱은 확실히 올라갑니다.
  제대로 하려면 공유 저장소(KV/Redis)가 필요합니다 — 지금 구조에서 추가 비용 없이 할 수 있는 최선입니다.
- **오류 메시지** — 예전에는 `error.message` 를 그대로 돌려줘서 DB 호스트명 같은 내부 정보가 노출될 수 있었습니다.
  이제 로그에만 남기고 화면에는 일반 문구만 나갑니다.
- **버그: 끊긴 DB 커넥션이 영구화되던 문제** — 실패한 프로미스를 캐시에 그대로 두는 바람에,
  한 번 DB 연결에 실패한 인스턴스는 살아 있는 동안 계속 실패했습니다. 실패한 프로미스는 이제 캐시에서 지웁니다.

> 429 응답이 두 종류가 됐습니다. `scope: 'ip'` 면 "이 방문자가 너무 빨리 눌렀다"(1분 뒤 다시),
> 없으면 "사이트 전체 일일 한도 소진"(내일 다시). 15개 페이지의 안내 문구가 이 값을 보고 갈립니다.
> **서버에서 `scope` 를 없애면 빨리 두 번 누른 사람에게 "오늘 한도를 다 썼다"고 잘못 안내됩니다.**

### 2. `/api/contact`

- 길이 제한(이름 100 / 이메일 254 / 제목 200 / 본문 5000), IP별 10분에 5회.
- **메일 헤더 인젝션 차단** — 제목에 CR/LF 를 넣어 `Bcc:` 같은 헤더를 덧붙이는 수법을 막습니다.
  제목으로 쓰는 값의 제어문자를 공백으로 바꿉니다.
- 이메일 정규식이 `[^@]+` 라 공백과 줄바꿈을 허용했습니다. `[^\s@]+` 로 바꿨습니다.
- 메일 발송이 실패해도 접수는 성공으로 응답하는 기존 동작은 그대로입니다.

### 3. 보안 헤더 (`vercel.json` 신규)

`X-Content-Type-Options`, `X-Frame-Options: SAMEORIGIN`(클릭재킹),
`Referrer-Policy`, `Permissions-Policy`, `Strict-Transport-Security`.
`/docs/`, `/scripts/`, `/data/` 에는 `X-Robots-Tag: noindex` — robots.txt 보다 강한 신호입니다.

### 4. 공급망

- `chartjs-adapter-date-fns` 가 **버전 없이** jsdelivr 에서 로드되고 있었습니다.
  즉 그쪽에서 새 메이저 버전이 나오는 순간 전 페이지의 차트가 조용히 깨질 수 있었습니다. `@3.0.0` 으로 고정했습니다.
- `package-lock.json` 을 추가했습니다. 없으면 배포할 때마다 `mysql2` / `resend` 의 하위 의존성이 새로 풀려서,
  털린 패치 버전이 그대로 프로덕션에 올라갈 수 있습니다.

### 5. XSS

프론트엔드는 대체로 이미 `escapeHtml()` 로 잘 막고 있었습니다. 남아 있던 곳은 하나:
Twelve Data 응답의 날짜 문자열(`ep.peakDate` / `ep.recoverDate`)이 `innerHTML` 로 그대로 들어갔습니다.
15개 페이지 45곳에 `escapeHtml()` 을 씌웠습니다. (한국 종목 이름은 저장소의 `kr-tickers.js` 에서 오고
`textContent` 로 출력되므로 원래 안전합니다.)

### 6. 구조화 데이터가 깨져 있던 문제

생성기가 `<script type="application/ld+json">` **안쪽 값에도** `escapeHtml()` 을 쓰고 있었습니다.
JSON 블록 안에서는 HTML 엔티티가 풀리지 않기 때문에, 구글이 `S&P500` 을 `S&amp;P500` 으로 읽고 있었습니다
(블로그 3곳 + 종목 리포트 6곳). JSON 규칙으로 인코딩하는 `jsonLd()` 를 따로 두고 그걸 쓰게 했습니다.

## 일부러 안 한 것 (건드리면 위험)

### CSP(Content-Security-Policy) — 넣지 않았습니다

애드센스, 쿠팡 파트너스, jsdelivr, 트레이딩뷰가 전부 외부 스크립트를 동적으로 더 불러옵니다.
특히 **애드센스는 광고를 그리면서 사전에 알 수 없는 도메인을 계속 추가로 부릅니다.**
CSP 를 조금이라도 좁게 걸면 광고가 안 뜨고, 그건 승인 심사에서 그대로 감점입니다.

정 넣고 싶으면 `Content-Security-Policy-Report-Only` 로 **몇 주 관찰한 뒤** 확정하세요.
바로 강제 적용하지 마세요.

### SRI(무결성 해시) — 넣지 않았습니다

`chart.js` 는 npm 패키지에 `.min.js` 가 없고 jsdelivr 가 직접 압축해서 만듭니다.
즉 정확한 해시를 사전에 검증할 방법이 없고, 추측한 해시를 넣으면 **차트가 통째로 안 뜹니다.**
꼭 하려면 `html2canvas` 처럼 `vendor/` 에 파일을 직접 받아 두고 우리 도메인에서 서빙하는 쪽이 안전합니다.

### `mdd.html` — 지우지 않았습니다

noindex 이고 아무 데서도 링크되지 않는 옛 페이지지만, 자기 API 키를 넣으면 실제로 동작하므로 남겼습니다.
없어진 `/api/trpc/twelvedata.timeSeries` 를 계속 부르고 있어서 **백엔드 조회가 항상 실패하던 것만** 고쳤습니다.

## 확인 안 된 것

- IP별 속도제한은 서버리스 인스턴스마다 따로 셉니다. 인스턴스가 여러 개로 늘어나면 실효 한도도 그만큼 늘어납니다.
  악용이 실제로 관측되면 공유 저장소 기반으로 옮겨야 합니다.
- `data/kr/*.json` 은 외부 시세 소스에서 받아 저장소에 커밋됩니다. 지금은 숫자만 렌더링에 쓰이고
  종목명은 저장소 목록에서 오므로 안전하지만, 나중에 이 JSON 의 **문자열 필드**를 화면에 쓰게 되면 그때는 이스케이프가 필요합니다.
